# Local Production-v1 Lessons

Date: 2026-08-09

## What proved effective

1. **Candidate identity must lead every installation.** The full wheel digest prevented smoke
   results from silently attaching to a superseded 1.0.0 build. Version text alone is insufficient.
2. **Protocol discovery must work before repository creation.** `forge agent protocol`, pre-init
   pack listing, and pack inspection gave both native agents the workflow vocabulary before any
   trust or mutation occurred.
3. **Readiness is a separate concept from transition legality.** Naming missing artifact roles and
   current check prerequisites in `blockers` and `ready_actions` prevented agents from presenting a
   merely legal future transition as executable now.
4. **Owner gates work best when consequences are generated by the CLI.** The four-file context
   preview, temporary lock disclosure, unmanaged-byte boundary, and zero-event statement gave the
   owner a concrete decision rather than a vague request for permission.
5. **Authority and authorship must remain separate.** `direct-codex` and `direct-claude` claims,
   non-authentication labels, and optional session references preserve useful provenance without
   pretending a same-user workspace is an identity boundary.
6. **Pack-compatible smoke fixtures matter.** Two distinct discover artifacts exercised the real
   `software-basic` contract and avoided the earlier one-file fixture contradiction.
7. **External and governed evidence should not be conflated.** GitHub CI can be directly observed
   and recorded with exact heads and run IDs while still being labeled external to FORGE's local
   evidence chain.

## Process improvements to retain

- Freeze source before building, then run every artifact-bound check against one immutable wheel
  and sdist identity.
- Use unique external Windows test roots. A validation project nested under another governed or Git
  repository can inherit policy and produce harness failures unrelated to the candidate.
- Invoke pipx through an interpreter that actually has pipx installed; the target Python used by a
  smoke environment need not contain the pipx application.
- Preserve failures and classify them before changing code. Network isolation, temp-directory
  access, missing symlink privilege, and upstream pipe cancellation were environment or harness
  findings, not reasons to weaken product gates.
- Refresh derived context only after a complete preview and explicit owner direction. Always compare
  it with authoritative `doctor` and `status` output before trusting cold-agent guidance.
- Keep exact receipts verbatim and put interpretation in a separate `Read` statement. This protects
  the distinction among claims, checks, evidence, verification, acceptance, and closure.

## Follow-up backlog

### Higher priority

1. Add a focused native or integration test that places owner bytes outside the managed markers,
   changes the canonical managed content, applies regeneration, and proves rewrite-path byte
   preservation. The current replacement native smoke proved the no-change path.
2. Add an explicit stale-context signal or safe automatic freshness design so a cold agent cannot
   mistake an old derived context for current governed state.
3. Investigate the Windows console replacement character used for the initiative-title separator
   and choose output that renders consistently in supported terminals.
4. Keep privileged Windows symbolic-link cases in the evidence backlog and run them before making a
   broader Windows filesystem-security claim.

### Ergonomics and documentation

5. State the vendor mapping prominently: Codex targets `AGENTS.md`; Claude targets `CLAUDE.md`.
6. Make state-inspection verbs more uniform, particularly `acceptance show` versus the neighboring
   `artifact list`, `check list`, and `evidence list` commands.
7. Clarify that the mutation command is `artifact add` even though prose and receipts describe the
   resulting artifact as registered.
8. Consider inferring `text/markdown` for Markdown artifacts while preserving an explicit
   `--media-type` override.
9. In compact claim rendering, consider showing the direct operator before configured authority so
   a quick reader is less likely to mistake agent-authored work for owner-typed work.
10. Explain that `--no-index` installation requires a complete local dependency wheelhouse, not
    merely the FORGE wheel.

## Boundaries that should not be relaxed

- Do not treat operator labels, chat approval text, session references, or filesystem access as
  authenticated owner identity.
- Do not treat a successful merge as proof that every CI check passed.
- Do not silently rebuild or replace the ignored candidate artifacts.
- Do not convert direct-agent success into managed-adapter compatibility.
- Do not convert this local candidate closeout into public-release authority.
- Do not remove the symlink tests merely because this host lacks privilege to create their fixtures;
  explicit skips are more honest than deleting the intended security coverage.

## Recommended successor work

Continue extended owner use with the preserved exact wheel. Collect friction in ordinary Codex and
Claude projects without changing candidate bytes. Address the higher-priority backlog through a new
bounded initiative if fixes would alter shipped code. Handle naming, signing, publishing, hosted or
multi-user enforcement, and public operational readiness only in a separate public-release
initiative with its own acceptance and evidence.
